# The move: Iteration

**Same ad. New front door.**

An iteration does not move the concept. It only changes who stops to read it.

---

## What an iteration is

Everything stays. You change the way in.

This is the cheapest test you will ever run, and it is the one most accounts skip, because changing one line feels too small to bother with. It is not. On cold traffic the opening decides who reads the other 1,000 words.

---

## The layer table

| Layer | Moves? |
| --- | --- |
| ICP | No |
| Use Case | No |
| Angle, belief shift | No |
| Angle, emotion | No |
| Awareness | No |
| Bucket | No |
| Format | No |
| Length | No |
| Audience, budget, page, landing page | No |

**Not one layer of the master concept moves.** That is what makes an iteration an iteration.

If any row above changes, you are running a new concept and it gets named NN, not ITE.

---

## The beat map

**Changes: 1. That is the whole test.**

Everything else is copied word for word, including the close.

### The one exception

If the echo close at beat 19 names the same object as the hook, it has to move with the hook or the ad ends on something it never opened with.

Decide that once, and keep the decision identical across every door you test, so the comparison stays clean.

---

## The thing people get wrong

**On a static ad, the headline and the image are one unit.**

You cannot iterate the hook and hold the image still. A hook about a sock sitting over a picture of a hospital letter reads as a mismatch and kills the click. The image rules say it directly: a changed headline voids its image direction.

So the variable is not "the hook". It is **the opening unit: headline plus image together.** That is still one variable. It is just bigger than it looks.

---

## Building the doors

Three or four openings into the same ad. Rules:

1. **Every door lands on the same bridge line**, the sentence that hands over to the body copy. Keep it identical across all of them. That is the seam and it has to hold.
2. **Every door comes from inside the script.** Beats 3, 4, 6, 7 and 14 are full of concrete moments. Do not invent a new one.
3. **Name each door by hook style**, using the client's own locked list. If none fits, say so and flag it as a candidate. Never quietly add a new style to the list.
4. **Vary the style, not just the scene.** Three doors in the same hook style tells you far less than three different styles. Check this before you brief.
5. **One image per door**, sourced from that door's own hook.

---

## Naming

`ITE`, and bump the version. Same angle code, same batch. Only the version moves.

If you find yourself wanting a new angle code, you are not iterating.

---

## Failure modes to watch for

1. **Two beats moved.** Then it is not an iteration. Recount.
2. **The bridge line drifted.** Each door now hands over differently and you are testing the seam as well.
3. **All the doors are the same hook style.** You tested scenes, not styles, and probably learned less than you think.
4. **The image did not move.** Headline and image are one unit. A mismatched pair loses the click before the copy gets a chance.
5. **Spending the payoff.** If the hook uses a line that the control saves for deep in the ad, the ad now has nothing left to land on. That can still be the right call, but name the risk out loud in the brief.

---

## How to read the result

One question: **which door do they walk through?**

Judge on click through first, then the client's primary metric. A door can win attention and still lose the sale, and that is a real and useful result.

| Outcome | What it means | Next |
| --- | --- | --- |
| A door beats the control on both | Make it the new control and iterate again |
| A door wins clicks but loses sales | The door attracted the wrong reader. Useful. Note who it pulled |
| All doors land level | The opening is not the lever here. Go to a use case swap |

Run all doors at once against the control. Hooks are cheap and there is no reason to run them one at a time.
